# Sendspin client library, pinned BELOW 7.0 on purpose.
#
# ledfx asks for a bare `aiosendspin>=4.0.0`, so an unconstrained build picks up
# whatever is newest - and aiosendspin 7.0 replaced the client's `client_id`
# argument with an X25519 `identity` plus a required `pairing_store` (the Noise
# handshake). Against 7.0+ every ledfx connection attempt dies before it reaches
# the network with:
#
#   SendspinClient.__init__() got an unexpected keyword argument 'client_id'
#
# 6.x speaks the pre-Noise ("legacy") wire format, which Music Assistant still
# accepts by default (its Sendspin provider defaults `allow_legacy_clients` to
# true). Upstream LedFX caps the same range on main (aiosendspin>=6.0.5,<7.0.0);
# we pin the exact last 6.x release so the image is reproducible. patch_backend.py
# asserts the resolved version still accepts `client_id`, so a drifting pin fails
# the build loudly instead of shipping a bridge that can never connect.
#
# To move past this: bump the ledfx SHA to a commit whose Sendspin client builds
# an `Identity`/`ClientPairingStore`, then raise this pin in the same change.
aiosendspin==6.1.1
